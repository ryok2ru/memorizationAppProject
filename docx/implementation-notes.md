### 自分で判断した点

- **評価ボタンの表記**: `GRADE_LABELS`（もう一度 / 難しい / 普通 / 簡単）を削除し、既存の `GRADE_NAMES`（Again / Hard / Good / Easy）に一本化した。結果画面は英語 1 行だけにした（以前は英語と日本語の 2 行）。フラッシュカードのスワイプ中のラベルも同じ表記。
- **プレビュー（↻ / N日後）の判定**: 「当日中に再出題される」は due の日付ではなく、更新後の state が 1 か 3 か（= 6-3 手順 4 でキュー末尾に追加される条件）で判定する。`isShortTermState()` を `domain/fsrs.ts` に置き、`session.applyRating()` も同じ関数を使うので、ボタンの「↻」と実際の再出題が必ず一致する。23:55 の評価で 10 分ステップが翌日に食い込む場合も「↻」になるが、セッション内では再出題されるので表示として正しい。「N日後」は `scheduled_days`（Review なら 1 以上）。
- **↻ の注記行**は、4 つのボタンのどれかが「↻」のときだけ描画し、それ以外は行ごと出さない（レイアウトは 1 行分動く）。タイプ入力の Good / Easy ボタンにはプレビューを付けていない（6-4 のタイプ入力の記述にプレビューがないため）。
- **フォルダカードと単語行**: ホームのフォルダは `📁` 絵文字付きのカード（`--surface` 背景、1px の枠、薄い影、角丸 12px）。単語一覧と検索結果は背景なし・角丸なしで、`--border` の区切り線だけのリスト行。絵文字はアイコン画像を増やさないための選択で、iOS では標準で描画される。
- **「…」メニューの撤去**: 取込しか入っていなかったので、ボタンごと削除した。取込の入口は「＋」→ `<dialog>` のアクションシート（新規 `ActionSheet` コンポーネント）。ホームのフォルダメニューは既存の実装のままにした。
- **複数選択**: 選択モード中は行の `<label>` 全体でチェックを切り替え、編集画面へは遷移しない。右上は「完了」だけになり「＋」と「選択」は隠す。削除は `deleteWords(ids)`（`deleteWord` はこれを使うよう書き換え）で ReviewLog も含めて 1 トランザクション。削除後は選択モードを抜ける。単語 0 件なら「選択」は非活性。
- **スワイプ削除**（`SwipeRow` コンポーネント）: Pointer Events で実装し、`touch-action: pan-y` で縦スクロールはブラウザに任せる。10px 動くまでは判定しない。横が縦より大きければスワイプ（`setPointerCapture`）、そうでなければ以後無視。左方向のみ（右へは動かない）。ゴミ箱は行の右端に赤背景で置き、移動量 ÷ (行幅 × 40%) を不透明度と拡大率にして徐々に出す。40% 以上で離すと `onDelete`、未満なら 0.2 秒のアニメーションで戻す。判定できる距離を動かした後の `click` は捕捉して潰し、行のリンクへ遷移しない。PC のマウスでも動くよう、リンクのネイティブドラッグ（`dragstart`）を止めている。
- **削除の保留**: スワイプ確定で行を一覧から隠し、`{ word, timer }` を ref に持つ。5 秒後、または単語一覧のアンマウント（戻る、編集画面へ、学習開始など）の時点で `deleteWord()` → バッジ更新 → 再読み込み。「元に戻す」はタイマーを止めて行を戻すだけ。保留中に別の行をスワイプしたら、先の保留分を先に確定してから新しい保留にする（トーストは常に 1 件）。アプリを閉じた（ページを破棄した）場合は削除されず単語が残る。設計書に記載のない挙動なので、安全側（残る）にした。
- **取込画面**: 別ルートにせず、単語一覧が `importFile` を持っている間だけ `ImportScreen` を描画する（ファイル内容はメモリ上にあるだけで、再読み込みで消える）。初期値の優先順（見出し語 > 前回の保存値 > 既定の並び）と、区切り・見出しの変更時に割り当てを作り直すことは 10-3 に書いた。前回の区切りは「1 行目にその文字が含まれるとき」だけ優先し、含まれなければ自動判定に落とすので、CSV の後に TSV を読んでも誤判定しない。区切りのセレクトの `value` にはタブ文字を入れず `comma / tab / semicolon` のキーを使う。
- **見出し語**: `startsWith`（小文字化・BOM 除去・trim 後）で判定する。旧実装は 1 列目が「英単語 / englishTerm / english」で始まるときだけ見出しとしていたが、新実装はどの列でもよく、「日本語訳」「メモ」だけの見出しでも ON になる。
- **列の割り当ての一意性**は UI 側で担保する（同じ役割を別の列で選ぶと元の列は「使わない」に戻る）。`hasEnAndJa()` は念のため件数も確認する。
- **settings の保存タイミング**: 「取り込む」を押した直後、単語を書き込む前に保存する。取込がバリデーション等で 0 件でも設定は残る。
- **セッション終了の遷移（8）**: Chromium（Playwright）ではボタン・スワイプ・タイプ入力のいずれの経路でも、再出題分を含めて最後の評価の直後に結果画面へ遷移し、報告された現象は再現できなかった。iPhone 固有の要因として疑わしかった「`updateBadge()`（`navigator.setAppBadge`）の完了を待ってから遷移する」構造をやめ、評価を反映した直後に `navigate('/study/result')` を呼ぶよう `useStudy` を変えた。バッジは結果画面の表示時に更新される（既存の処理）ので、遷移がバッジ更新に依存しなくなった。`✕` の途中終了も同じ関数で遷移する。実機で再発する場合は、この変更でも直っていないことになるので、その旨を知らせてほしい。
- **横断検索**: 1 文字以上入力したときだけ `listAllWords()` で全単語を読む（ホーム表示のたびには読まない）。300ms のデバウンス、英語・日本語訳の小文字部分一致、英単語順、100 件で打ち切って「さらに絞り込んでください」を出す。検索中もサマリーカード・ストリーク・状態別割合は表示したまま、フォルダ一覧だけを結果に置き換える（7-2 の記述どおり）。結果行のタップ先は単語フォームで、そこから戻るとホームではなくその単語のフォルダに戻る（単語フォームの既存の戻り先）。
- **設定画面の取込の説明文**を新しい入口（＋ → CSV/TSV を取り込む）と取込画面の内容に合わせて書き換えた（7-8 の「CSV/TSV 取込の説明」の範囲内）。

## 自分で判断した点

- 単語フォームの「必須項目が空」は保存ボタンの非活性だけで示し、赤字は文字数超過のときだけ出す（7-4 は「超過項目の下に赤字で理由」）。
- フォルダ行の「…」は `<dialog>` のアクションシート（名前を変更 / 削除 / キャンセル）。
- モード選択でキューが空のときのタイトルは復習側の文言（「全フォルダを復習する」「学習を始める（フォルダ名）」）。
- 単語一覧の検索は英語・日本語訳を小文字化した部分一致。300ms のデバウンス。
- 結果画面の「当日初の学習」は、セッション開始時刻より前に当日の ReviewLog が無かったかどうかで判定する。
- フラッシュカードのスワイプは Pointer Events で実装。8px 未満の移動はタップとして反転に使う。移動量 60px 以上で方向確定。表面ではスワイプもボタンも無効。
- タイプ入力では判定後にメモを表示する（設計書に記載なし。表面では見せない）。
- 結果画面で 1 枚も評価していないときの「次回最も早い復習日」は「—」。
- 10-4 の「書き込み失敗は 1 回再試行」は評価保存（`rateAndSave`）に実装。その他の書き込みは失敗時にメッセージを表示するだけ。`QuotaExceededError` は「端末の空き容量が不足しています」。
- バックアップ読み込み時の settings は既定値とマージし、`id` と `schemaVersion` を固定する。
- 通知の `finishToday()` は設計どおり `lastNotifyScheduledAt` / `lastNotifyItemCount` を保存してから URL を開く。件数 0 の日は項目に含めないため、`lastNotifyItemCount` は「項目のある日数」になる。
- `npm run build` の `base` は `BASE_PATH` 環境変数（既定 `/`）。GitHub Actions では `/<リポジトリ名>/`。
- 8-5 の永続化要求は、最初のフォルダ作成または単語登録時に一度だけ呼ぶ。
- バッジ更新は起動時（ホーム表示時）、セッション完了時、単語の追加・削除・取込・進捗リセット・バックアップ読み込み時に行う。
