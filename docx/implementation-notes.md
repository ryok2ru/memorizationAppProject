### 設計書との差異・残した不整合

- **7-9 は ConfirmDialog の行だけでなく、表の下に段落を 1 つ足した。** 依頼は「ConfirmDialog の行に追記する」だが、外側タップは ConfirmDialog 以外（QuitSheet、InfoSheet、入力ダイアログ、フォルダの「…」メニュー、移動先の選択、並べ替えの基準選択）にも同じように付く。行だけの追記だと設計書が実装より狭くなるので、対象の一覧・「開始と終了の両方が外側」の規則・取込画面が対象外であることを 1 段落にまとめて表の下に置いた。
- **外側タップの判定は、`event.target` ではなく座標で行う。** `<dialog>` の背景（`::backdrop`）のタップはダイアログ要素自身に届くが、ダイアログには 20px の余白（`padding`）があり、その余白を押したときも同じ要素に届く。`target === dialog` で判定すると、中身の縁を押しただけで閉じてしまう。`getBoundingClientRect()` の 4 辺と指の座標を比べる形にした（ヘッドレスブラウザで、余白を押しても閉じないことを確認した）。
- **並べ替えボタンの基準名と矢印の間には、今までと同じだけ余白が残る。** 「表示例: 登録日↓」は並び順を示したもので、間を詰める指示とは読まなかった。基準名は固定幅（`3em + 16px`）の中央、矢印は 44px のタップ領域の中央にあるので、左右を入れ替えた今も見た目の間隔は以前（↓登録日）と同じ。幅の固定と 44px の確保を崩さずに間を詰める方法が無いため、鏡写しにするだけにとどめた。
- **☆ の縦の中心をそろえるための CSS は足していない。** 上部バーのボタンは全部 `min-height: 44px` の `inline-flex`（`align-items: center`）で、`.header` と `.header-side` も `align-items: center` なので、円を 36px から 24px に縮めてもボタンの高さ（44px）は変わらず、中心はそろったままになる。ヘッドレスブラウザで、☆ の円・「キャンセル」・「保存」の中心 Y が 3 つとも 26px で一致することを確認した。

### 自分で判断した点

**外側タップで閉じる（`src/ui/components/modal.ts`）**

- 判定は `modal.ts` に 3 つ足した。`isOutside(edges, x, y)`（座標が矩形の外側か）、`outsidePress()`（押し始めと離した位置の両方が外側のときだけ `true` を返す小さな入れ物）、`useCloseOnOutside(onClose)`（`<dialog>` にそのまま展開する `onPointerDown` / `onPointerUp` / `onPointerCancel`）。前の 2 つは DOM も React も触らない純粋な関数なので、既存のテスト環境（node）のまま単体テストできる（`src/ui/components/modal.test.ts`）。
- `click` ではなく `pointerdown` / `pointerup` を使った。依頼の「開始と終了の両方が外側」を見るには 2 つのイベントが要る。加えて、キーボードの Enter で出る `click` は座標が (0, 0) になり、それを外側と数えると中身のボタンを Enter で押しただけで閉じてしまうが、Enter は pointer イベントを出さないのでこの形なら誤って閉じない。
- `pointercancel`（指を滑らせてシートの中身をスクロールしたときなど）では「押し始め」を捨てる。次の `pointerup` で閉じないようにするため。
- 閉じる先はどのダイアログも既存の「キャンセル」と同じ関数（`onCancel` / `onClose`）に渡した。新しい経路を作っていないので、キャンセルと動作が食い違うことがない。フォルダの削除・単語の一括削除・変更の破棄・移動先の選択のどれでも、外側タップの後に件数や内容が変わっていないことをヘッドレスブラウザで確認した。
- 付けた先は `ConfirmDialog`、`InputDialog`、`InfoSheet`、`QuitSheet`、ホームの `FolderMenu`、単語一覧の `MoveDialog` と `SortSheet` の 7 つ。アプリ内の `<dialog>` はこれで全部で、取込画面（`src/ui/screens/Import.tsx`）は `<dialog>` を使わない全画面なので、依頼どおり手を入れていない。
- フックは JSX の中ではなく各コンポーネントの本体で呼び、戻り値を `{...outside}` で展開している。呼び出しが必ず 1 回・同じ順番になるようにするため。

**並べ替えの矢印を右側に（`src/ui/screens/WordList.tsx`、`src/ui/styles/base.css`）**

- JSX の 2 つのボタンの順番を入れ替えただけで、クラス・幅・`aria-label`・`data-testid` は変えていない。`.sort-dir` は 44px、`.sort-key` は `calc(3em + 16px)` のままなので、ボタン全体の幅（実測 102px）も基準を変えたときに動かないことも今までどおり。ヘッドレスブラウザで、基準を「登録日」から「アルファベット」に変えても 102px のままであること、矢印のタップ領域が 44 × 44px であることを確かめた。
- 読み上げの文言は変えていない。矢印は `並び順: 新しい順。押すと逆順`、基準名は `並べ替え: 登録日` のままで、位置が変わっても意味は同じ。

**☆ ボタンの縮小（`src/ui/styles/base.css`）**

- `.btn-favorite .favorite-circle` の `width` / `height` を 36px → 24px、`font-size` を 20px → 16px にしただけ。塗り（☆ = #E5E5EA / #3A3A3C、★ = `--hard`）と、タップ領域（`button` の `min-height` / `min-width` の 44px）には触れていない。
- 結果画面（7-7）の ☆ は円で囲まない別物（`--muted` の素の ☆）なので、今回の対象外として変えていない。依頼が「単語フォームと学習画面の ☆ ボタンの円」と書いているため。

### 設計書との差異・残した不整合

- **「破棄して終了」の DB の書き戻しは 1 トランザクションだが、セッション状態のほうは `undoLast` を全件繰り返している。** 依頼の「undo スタックを全件巻き戻す処理として実装し、1 トランザクションで行う」は、DB の書き込み（`db/repo.ts` の `revertRatings`）が 1 トランザクションで、メモリ上の状態（`undoAll`）は `undoLast` の繰り返し、という形にした。状態のほうは純粋な関数で DB を触らないので、繰り返しても書き込みは増えない。同じ単語を 2 回以上評価していても、書き戻す値はその単語の一番古い `before`（＝開始前の値）だけで、`revertRatings` の中で 1 単語 1 回の `update` にまとめている。
- **破棄の後は結果画面を出さないので、`endedEarly` も `finishedAt` も使わない。** セッションはモード選択へ移った時点で捨てる（`setSession(null)`）。モード選択で開始すると新しいセッションが作られるので、巻き戻した状態は誰も見ない。それでも `discardAndSave` は巻き戻した状態を返している（開始時点に戻ることをテストで確かめるため）。
- **結果画面の一覧の「次回の復習」は、その単語の最後の評価の due を出す。** 設計書 7-7 は「評価後の due」としか書いていない。評価の列は依頼どおり「最初に押した評価」だが、日付のほうを最初の評価のものにすると、Again で 10 分後になったあと再出題で Good にした単語が「今日」と出てしまい、実際の次回（数日後）と食い違う。表示が実際の予定と一致するほうを採った。
- **☆ の「薄いグレー」は `--muted`（#8E8E93）にした。** 7-4・7-6 の円で囲む ☆ の背景色（#E5E5EA / #3A3A3C）は塗りつぶしの色で、文字にそのまま使うと背景と見分けが付かない。ここは円で囲まない素の ☆ なので、既存の補助文字の色を使った。
- **結果画面の一覧は、評価が 0 件のときは枠ごと出さない。** 途中終了で 1 件も評価していない場合に「評価した単語」の空の枠が残るのを避けた。設計書 7-7 に明記した。
- **ホームの横断検索の結果に左スワイプ（削除）は付けていない。** 依頼は右スワイプのお気に入りを「ホームの横断検索の結果とお気に入り一覧でも同じ動作にする」で、削除には触れていない。7-2 にも削除の記述は無いので、`SwipeRow` の `onDelete` を渡さない形にした（渡さない向きはそもそも指に追従しない）。

### 自分で判断した点

**✕ の 3 択（`src/ui/components/QuitSheet.tsx`、`src/ui/screens/Flashcard.tsx`、`src/ui/screens/Typing.tsx`）**

- シートはフォルダのメニュー（7-2）と同じ形にした。`dialog.sheet` の中に `.menu-buttons` を置き、`.btn-outline`（強調色）/ `.btn-outline-danger`（Again 色）/ `.btn-outline-quiet`（薄い枠）の 3 つを並べただけで、新しいクラスは足していない。ヘッドレスブラウザで 3 つとも高さ 48px・幅 358px・色は #2E5090 / #FF3B30 / #D1D1D6 の枠であることを確かめた。
- 見出しは今までの確認ダイアログと同じ「セッションを終了しますか？」のまま。2 つの終了が並ぶので、どちらを選ぶかはボタンの文言で分かる。
- フラッシュカードとタイプ入力で同じ部品を使う。どちらも ✕ の `onClick` は今までどおり `setConfirmQuit(true)` だけで、中身が `ConfirmDialog` から `QuitSheet` に変わった。

**評価の破棄（`src/app/session.ts`、`src/db/repo.ts`、`src/ui/useStudy.ts`）**

- `revertRatings(entries)` は、`undo` スタックをそのまま（古い順で）受け取り、単語ごとに最初に出てくる `before` だけを Map に集めてから 1 トランザクションで書き戻す。ReviewLog は `bulkDelete` でまとめて消す。既存の `revertRating`（1 件用）はそのまま残した。
- `discardAndSave` は `undoAndSave` と同じ形（2 回まで再試行、`QuotaExceededError` は区別）にそろえた。失敗したときのメッセージも取り消しと同じ「取り消しに失敗しました」。
- **破棄の後の遷移で、`useStudy` に `leaving` の ref を足した。** HashRouter の遷移は `hashchange` を待つので、`navigate()` の直後に `setSession(null)` すると、まだ学習画面が描かれている状態で「セッションが無い」と判定され、ホームへ戻る `useEffect` が先に走ってしまう（実際にヘッドレスブラウザで `#/` に着いた）。破棄の遷移中だけこの `useEffect` を止めることで、モード選択へ着くようにした。ref はこの画面が消えるときに一緒に消える。
- バッジの更新は `updateBadge()` を破棄の直後に呼ぶ。破棄で「今日の復習」の件数が開始前に戻るため。

**スワイプ評価の確定量（`src/ui/screens/Flashcard.tsx`）**

- `confirmDistance(cardWidth)` を切り出して単体テストできるようにした。カード幅は指を置いた時点（`onPointerDown`）に `cardRef.current.clientWidth` で測って state に入れ、そのセッション中の判定・色・傾きすべてに同じ値を使う。`ResizeObserver` は入れていない（スワイプの途中でカード幅が変わることはない）。
- 幅が測れないときの 85px は、390px 幅の iPhone でのカード幅 342px の 25%。ヘッドレスブラウザでも実測 342px → 85.5px で、依頼の「約 85px」と一致した。
- 縦（Again / Easy）の確定量にもカード幅の 25% を使う。依頼が「確定する移動量」を 1 つの値として書いているため、軸ごとに変えていない。

**右スワイプでお気に入り（`src/ui/components/SwipeRow.tsx`、`src/ui/screens/WordList.tsx`、`src/ui/screens/Home.tsx`）**

- `SwipeRow` の `onDelete` を任意にし、`onFavorite` と `favorite` を足した。渡された向きにだけ指に追従する（`onDelete` が無ければ 0 より左に動かない）ので、ホームの横断検索では右にしか動かない。
- 下地（`.swipe-under`）は左右で共通のクラスにし、`.delete`（右端・Again 色・🗑）と `.favorite`（左端・Hard 色・☆ / ★）で位置と色だけを分けた。`.swipe-trash` は左右で使うので `.swipe-icon` に名前を変えた。
- 確定量の定数は削除と共通の 20%（`SWIPE_RATIO`。旧 `DELETE_RATIO` を改名）。依頼が削除と同じ 20% なので、2 つに分ける理由がない。
- 右スワイプで確定したときは行を残すので、`offset` を 0 に戻してから `onFavorite()` を呼ぶ。削除のように行幅いっぱいまで送らない。
- 切り替えの保存は `setFavorite()` を呼んで一覧を読み直すだけ（`reload()`）。お気に入り一覧では ★ を外した行が読み直しで消える。戻るアニメーション（0.2 秒）の間に読み直しが終わるので、行の ★ はすぐ変わって見える。
- ホームの横断検索は `allWords` と集計（`data`）の 2 つを読み直す。「★ お気に入り」カードの件数もその場で変わる。

**結果画面の評価した単語（`src/app/session.ts`、`src/ui/screens/Result.tsx`、`src/domain/dates.ts`）**

- 出題順は `session.queue` を先頭からたどって重複を飛ばした順にした（`ratedEntries`）。再出題でキュー末尾に足された分は 2 回目以降なので自然に落ちる。評価していない単語（未出題、保存に失敗した分、取り消した分）は `firstRating` が無いので含まれない。
- `ratedEntries` は単語 id だけを返し、本文は結果画面が `getWords()` でまとめて読む。`session.ts` が DB の Word を持たずに済み、テストも id だけで書ける。
- 「今日 / 明日 / N日後」は `dates.ts` に `reviewDayLabel` を切り出し、一覧の `relativeDueLabel` からも呼ぶようにした（「未学習」と「N日超過」だけが `relativeDueLabel` 側に残る）。
- 行は 5 列のグリッド（44px / 1fr / 1fr / auto / auto）。英単語と日本語訳の列を `minmax(0, 1fr)` にすることで、長い文字列でも列が広がらず `text-overflow: ellipsis` が効く。390px 幅で日本語訳が省略されることをヘッドレスブラウザで確かめた。
- ☆ の状態はこの画面の中だけで持つ（`favorites` の上書き）。押した時点で `setFavorite()` を呼び、失敗したら表示を元に戻して「保存に失敗しました」を出す。結果画面は再読み込みしないので、一覧全体を読み直す必要がない。
- 枠は既存の `.stat`（`--surface` の角丸）を使い回した。「次回最も早い復習日」の枠と同じ見た目になる。

### ヘッドレスブラウザで確認した内容

390 × 844（iPhone 相当）の Chromium で、`npm run preview` に対して次を確認した。

- **✕ の 3 択**: 見出し「セッションを終了しますか？」、ボタンは「結果を保存して終了」（#2E5090）/「結果を破棄して終了」（#FF3B30）/「キャンセル」（枠 #D1D1D6）で、3 つとも高さ 48px・幅 358px。シートの下端が画面下端（844px）。キャンセルで学習画面に戻る。
- **破棄**: 1 語を評価した状態（words の state = 1 / reps = 1、reviewLogs 1 件）から「結果を破棄して終了」を押すと、URL が `#/study/select?scope=<フォルダ id>` になり（結果画面は出ない）、IndexedDB の全単語が state = 0 / reps = 0、reviewLogs が 0 件に戻った。`favorite` は変わらない。タイプ入力（英→日）で 3 語を Hard にしてから破棄した場合も同じ（reps > 0 の単語 0、ログ 0）。評価 0 件のときは「結果を破棄して終了」が `disabled`（「結果を保存して終了」は有効）。
- **確定量**: カード幅 342px → 確定量 85.5px。確定量の 6px 手前で離すと同じ単語のまま、6px 超えて離すと次のカードへ。確定量の 50%（43px）で評価色の不透明度が 0.425（0.85 の半分）、評価名「Good」が出る。

**移動先ダイアログ（`src/ui/screens/WordList.tsx`、`src/ui/components/modal.ts`、`src/ui/styles/base.css`）**

- **現在のフォルダの除外**は、変更前の実装でも一覧と「移動先が無い」の判定の両方で `folderId` を除いていた（Chromium で再確認）。除外を純粋関数 `moveTargets(folders, currentId)` にまとめて、一覧の描画と「移動先のフォルダがありません」の判定が必ず同じ配列を見るようにし、`WordList.test.ts`（新規）で確認している。見出し「N件の移動先」の N は選択した単語の件数で、フォルダの数ではない。
- **青い枠の原因**は、ダイアログの既定の枠線（`dialog { border: none }` 済み）でも行の border（`button { border: none }` 済み）でもなく、**行ボタンのフォーカス枠**と判断した。根拠は WebKit のソース: `showModal()` の focusing steps（`HTMLDialogElement::runFocusingSteps` → `runFocusingStepsForAutofocus` → `Element::focus()`、trigger は `Other`）は最初のフォーカス可能要素（= 最初の行のボタン）に `FocusVisibility::Visible` でフォーカスを置くので、**タップで開いても `:focus-visible` に一致**し、UA の `outline: auto`（`-webkit-focus-ring-color`、青）が描かれる。行は `.dialog-list`（`overflow-y: auto`）の幅いっぱいなので、要素の外側に描かれる枠の左右（先頭の行は上も）が切り取られ、「途切れた枠」に見える。Chromium はタップ後のスクリプトによるフォーカスを `:focus-visible` にしないため再現しない（`:focus` だけが最初の行に付いていた）。WebKit は Mac / iOS ではボタンをタップでフォーカスしない（`HTMLFormControlElement::isMouseFocusable` が false）ので、行をタップした瞬間の枠ではない。
- **対処**: (1) `syncModal(el, open)`（新規 `modal.ts`）で `showModal()` の直後に `el.focus()` を呼び、開いたときのフォーカスを最初の行ではなく**ダイアログ自身**に置く。`<dialog>` に `tabIndex={-1}` を付けて確実にフォーカス可能にし、`dialog:focus { outline: none }` でダイアログ自身の枠は出さない。(2) `:focus:not(:focus-visible) { outline: none }` を全体に付け、タップによるフォーカスでは枠を出さない。(3) キーボード（Tab）で行に来たときの枠は `.dialog-list > button:focus-visible { outline-offset: -3px }` で行の内側に描き、スクロールの切り取りで途切れないようにする。UA の枠（`outline: auto`）は変えていない。
- `syncModal` は `ConfirmDialog` とホームのフォルダメニュー（`Home.tsx`）にも使い、すべてのダイアログで「開いたときに最初のボタンに枠が出ない」ようにした。`InputDialog` は入力欄に明示的にフォーカスを置く既存の処理（テキスト入力の枠は常に出るのが自然）なので変えていない。

- **軸の決定と追従**: `pointerdown` で `setPointerCapture` し、10px 動いた時点で `|dx| >= |dy|` なら横、そうでなければ縦に決める。以後はその軸の移動量だけを使い、カードの追従もその軸方向だけにした（横に決めた後に指が上下しても、カードは横にしか動かない）。「指に追従」を 2 軸で動かすと、判定に使わない方向にもカードが動いて評価が読みにくくなるため。
- **タップの判定**: 10px 未満のまま離したらタップ（軸が決まっていない = タップ）。以前の 8px から 10px に揃えた。`click` ハンドラでの反転は削除し、`pointerup` とキーボード（Enter / Space）だけで反転する。マウスでドラッグして戻したときに `click` が発火して裏返ってしまうのを避けるため。

- **傾き**: 横スワイプのみ `rotate(8deg × clamp(移動量 ÷ 120, -1, 1))`。縦は傾けない。
- **確定後の動き**: 120px 以上で離したら `.leave` クラス（`transition: transform 0.25s`）で画面外（横: `innerWidth + 200px`、縦: `innerHeight + 200px`）へ動かし、250ms 後に `rate()` を呼ぶ。評価を先に呼ぶと、抜けていく途中のカードの中身が次の単語に変わってしまうため。抜けている間は評価ボタン・↶・カードの `pointerdown` を無効にする。次のカードは `word` が一度 null になってからマウントされるので、抜けた位置から戻ってくる見た目にはならない。
