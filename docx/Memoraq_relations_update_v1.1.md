## 1. 決定事項の要約

**関係のルール**
- 関係は「階層」と「連結」の 2 種類。類義語・対義語などの関係タイプは決め打ちしない
- 階層の向きは常に上位→下位。1 つの項目は上位を複数持てる。循環は禁止
- 連結は「方向なし」と「単一方向」の 2 つ。対立などの意味は、連結に付ける任意のラベルで表す。ラベルの入力時は、過去に使ったラベルを候補に出す
- 階層にはラベルを付けない
- フォルダをまたいで自由につなげる
- 兄弟（同じ上位を持つ項目）の自動表示はしない

**ノード**
- 覚えない項目を「ノード」として置ける。関係の追加シートで、名前だけで作れる
- ノードはどのフォルダにも属さない。関係を見る画面と関係の追加シートの検索結果にだけ出る。単語一覧、ホームの検索、お気に入り、件数、学習には一切出ない
- ノードはカードにできる（裏とフォルダを入力）。カードもノードに戻せる（学習の記録は残し、再びカードにしたら続きから再開）
- 関係がすべてなくなるノードは、確認したうえで削除する

**画面**
- 単語一覧・ホームの検索結果・お気に入り一覧のタップ先は、カード詳細画面
- カード詳細画面は「カード」（ノードは「ノード」）と「関係」を切り替えて見る。編集ボタンは常に右上で、見ている側をその場で編集する。単語フォームは新規作成専用になる
- 関係側は上から「上位」「下位」「連結」。階層の行は木の記号（├ └）、連結の行は「— → ←」で表す
- 関係の追加は、区分ごとの「＋」から下から出るシートで行う。相手は全フォルダから検索する
- 関係の削除と変更は、関係側の編集モードで行う（⊖で削除、鉛筆で連結の向きとラベルを変更）
- グラフ画面は「関係」（深さ 1 段）と「階層」（アウトライン）の 2 モード。配置は上下＝階層、横＝連結。線は階層が実線の直角、連結が点線の曲線。ノードは点線の枠
- グラフ画面では、項目をタップすると中心が移り、中心をもう一度タップすると詳細画面を開く
- 結果画面の「評価したカード」の行をタップすると、中央のポップアップで「カード」「関係」を切り替えて見られる（閲覧のみ）
- 学習中（フラッシュカード、タイプ入力）は関係を出さない

**学習**
- New のみのセッションで、兄弟のカードを隣り合わせにしない（できる範囲で）
- 周辺だけの復習は今回は作らない（あとで）

## 2. 用語（1-3 に追加）

| 用語 | 定義 |
|---|---|
| 項目 | カードとノードの総称。関係の端になれるもの |
| ノード | 関係を見るためだけに置く、覚えない項目。名前だけを持ち、どのフォルダにも属さない。関係を見る画面（7-12、7-13、7-7 のポップアップ）と関係の追加シートにだけ出る。カードの数（「N枚」）には含めない |
| 関係 | 項目同士のつながり。「階層」と「連結」の 2 種類 |
| 階層 | 上位と下位のつながり。向きは常に上位→下位。1 つの項目は上位を複数持てる。循環は作れない |
| 上位・下位 | 階層で上にある項目と、下にある項目 |
| 連結 | 階層以外のつながり。「方向なし」か「単一方向」。任意のラベル（「対義」など）を付けられる |
| 兄弟 | 同じ上位を 1 つ以上共有するカード同士。画面には表示しない。New のキューの並べ替え（6-2）にだけ使う |
| カード詳細画面 | 項目を開いたときの画面（7-12）。「カード」（ノードは「ノード」）と「関係」を切り替え、見ている側をその場で編集する |
| グラフ画面 | 関係を図で見る画面（7-13）。「関係」と「階層」の 2 モード |

### 4-6. インデックス（行を追加）

| テーブル | インデックス | 用途 |
|---|---|---|
| edges | from | 項目から出る関係の取得 |
| edges | to | 項目に入る関係の取得 |

`nodes` は主キーだけで引き、名前の検索はメモリに読み込んでフィルターする。

### 4-7. スキーマ更新（行を追加）

| バージョン | 変更 | upgrade |
|---|---|---|
| 7 | テーブル `edges`（id, from, to）と `nodes`（id）を追加する（4-9、4-10）。他のテーブルは v6 と同じ | 不要。既存のレコードは変えない |

バックアップの `edges` と `nodes` は、無いときは空として読めるので `schemaVersion` は上げない（2 のまま）。

### 4-9. Edge（関係）［追加］

| 属性 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| kind | "hierarchy" \| "link" | 階層か連結か |
| from | string | 階層：上位の項目の id。連結：登録時に起点にした項目の id |
| to | string | 階層：下位の項目の id。連結：相手の項目の id |
| directed | boolean | 連結で単一方向なら true（from → to の向き）。方向なしの連結と、階層は false |
| label | string | 連結のラベル。0〜20 文字、trim する。階層は常に空文字 |
| createdAt | number | 作成日時（ms） |

項目の id は `words.id` か `nodes.id`。UUID は重ならないので、どちらのテーブルにあるかは id で引いて判定する。

### 4-10. NodeItem（ノード）［追加］

| 属性 | 型 | 説明 |
|---|---|---|
| id | string | UUID |
| name | string | 1〜200 文字。trim 後に非空。重複してよい |
| createdAt | number | 作成日時（ms） |
| updatedAt | number | 更新日時（ms） |
| saved | SavedCard \| null | カードからノードに戻したときの、カードの内容と学習状態。ノードとして作ったものは null |

`SavedCard` は Word から id・englishTerm・updatedAt を除いたもの（folderId、japaneseDefinition、memo、favorite、createdAt と FSRS 項目）。

ノードを `words` とは別のテーブルに置く理由：学習・件数・検索・バッジ・通知・統計など、`words` を読むすべての処理から、ノードを確実に外すため。Word の型と、`words` を読む既存の処理は変えない。

### 4-11. 関係の規則［追加］

| 規則 | 内容 |
|---|---|
| 自分自身 | 同じ項目同士はつなげない |
| 1 組 1 関係 | 2 つの項目の間には、種類と向きを問わず関係は 1 つだけ |
| 循環の禁止 | 階層で P を C の上位にするとき、P が C 自身か、C の下位（下位をたどって届く項目）なら追加しない |
| 上位の数 | 制限なし |
| フォルダ | 関係はフォルダをまたげる。カードを別のフォルダへ移しても、関係は残る |
| 孤立ノード | 関係が 1 つもないノードは残さない。削除によって関係が 0 になるノードは、同じトランザクションで削除する（4-12） |
| ラベルの候補 | 既存の連結のラベル（空を除く）を、新しく作られた関係から順に、重複を除いて最大 8 件 |
| 進捗リセット・☆・フォルダの移動 | 関係もノードも変えない |

### 4-12. カードとノードの切り替え、削除［追加］

いずれも 1 トランザクションで行う。

| 操作 | 処理 |
|---|---|
| ノードをカードにする | 同じ id で Word を作る。englishTerm は入力（初期値は name）、folderId・japaneseDefinition・memo・画像は入力（7-12）。saved があれば favorite・createdAt・FSRS 項目を saved から戻す（学習の続きから再開）。saved がなければ favorite = false、FSRS 項目は `newCardFields(now)`。`nodes` からは削除する。関係は id が同じなのでそのまま残る |
| カードをノードに戻す | 同じ id で NodeItem を作る（name = englishTerm、saved = Word の内容と FSRS 項目）。`words` からは削除する。ReviewLog と画像は消さずに残す。関係が 1 つ以上あるときだけ行える |
| 項目の削除 | その項目の関係をすべて削除する。カードなら ReviewLog と画像も削除する。ノードなら、画像が残っていれば削除する |
| 孤立ノードの連鎖 | 削除で関係が 0 になったノードも削除する。それによって別のノードの関係が 0 になれば、それも削除する（関係 0 のノードがなくなるまで繰り返す） |

孤立ノードが出るときの確認の出し方：

| 操作 | 扱い |
|---|---|
| 関係の ⊖（7-12） | 「元に戻す」は使わず、確認ダイアログ「関係がなくなるため、ノード「名前」も削除します。よろしいですか？」を出す（2 件以上なら「ノード N件」） |
| カード・ノードの削除、フォルダの削除、一括削除 | 既存の確認文の末尾に「関係がなくなるノード N件も削除します。」を添える |
| 単語一覧のスワイプ削除 | 確認は出さず、トーストを「削除しました（ノード N件も削除）　元に戻す」にする。「元に戻す」でどちらも戻る |

## 5. 学習セッション（6 章）

### 6-2. キュー構築［変更］

手順 3 と 4 の間に、次の手順を加える（以降の番号を繰り下げる）。

> 4. 種類が「New のみ」のときは、兄弟（同じ上位を 1 つ以上共有するカード。上位はカードでもノードでもよい）が隣り合わないように並べ替える。先頭から順に、直前に置いたカードの兄弟でない最初のカードを残りから選んで置く。そういうカードが残っていなければ、残りの先頭を置く。シャッフルが ON ならシャッフルの後に、OFF なら登録順を保ったまま必要な所だけを動かす形になる。復習のセッションでは行わない。

セッション内の再出題（6-3）で末尾に足すカードは、並べ替えの対象にしない。

### 6-4、7-6［変更］

学習画面（フラッシュカード、タイプ入力）には、関係を表示しない。

### 7-2、7-3 のタップ先［変更］

- 7-2「検索」：結果の行のタップで開く画面を、単語フォーム（編集）からカード詳細画面に変える
- 7-3「一覧の行」：「タップで編集へ」を「タップでカード詳細画面へ」に変える。お気に入り一覧も同じ
- 7-3「選択」と「左スワイプで削除」：孤立ノードが出るときの文面を 4-12 のとおりにする

### 7-4. 単語フォーム［変更］

新規作成専用にする。タイトルは「カードを追加」だけ。次の行はカード詳細画面（7-12）に移し、単語フォームからは外す。

- お気に入り（☆）（編集のみ）
- 削除（編集時）
- タイトルの「編集：カードを編集」、キャンセル・保存の編集時の記述

保存後は、今と同じく単語一覧へ戻る。関係は、保存したカードの詳細画面で後から足す。

### 7-7. 結果［変更］

「評価したカード」の行をタップすると（☆ボタンを除く）、カードのポップアップ（7-14）を出す。

### 7-12. カード詳細画面［追加］

カードとノードの両方を、この画面で表示する。

**共通**

| 要素 | 仕様 |
|---|---|
| 上部バー（通常） | 左：戻る。タイトル：カードは「カード」、ノードは「ノード」。右：カードは「☆ → 編集」（☆は 7-4 にあった共通の部品）、ノードは「編集」だけ |
| 切り替え | 上部バーの下に、「カード」（ノードは「ノード」）と「関係 N」（N はその項目の関係の数）の 2 択。見た目は単語一覧のフィルターと同じ。初期表示は、カードは「カード」、ノードは「関係」。開くたびに初期表示に戻す。編集モード中は押せない |
| 編集ボタン | 常に右上。「カード」（「ノード」）側で押すとその側の編集、「関係」側で押すと関係の編集に入る |

**カード側（通常）**

| 要素 | 仕様 |
|---|---|
| 内容 | 表（大きく）、裏、画像（4-8。表示する面の設定にかかわらず出す）、メモ（空なら見出しごと出さない） |
| 学習の状態 | 内容の下に枠を置き、状態アイコンと名前（5-3）、次の復習を表示する。次の復習は「3日後（10/13）」の形。今日なら「今日」、New なら「未学習」 |

**カード側（編集）**

| 要素 | 仕様 |
|---|---|
| 上部バー | 左「キャンセル」、右「保存」。☆と戻るは出さない |
| 項目 | フォルダ、{表}、{裏}、メモ、画像。仕様・バリデーション・文言は 7-4 の同名の項目と同じ |
| 保存 | 7-4 の保存と同じ処理。保存後は編集を抜けて通常の表示に戻る。フォルダを変えた場合は、画面下に「1件を「フォルダ名」に移動しました」を 4 秒表示する |
| キャンセル | 変更があれば「変更を破棄しますか？」 |
| ノードに戻す | 下部に「ノードに戻す」（強調色の枠）。関係が 1 つもなければ出さない。押すと確認「このカードを学習から外し、ノードにします。フォルダから外れ、関係を見る画面にだけ表示されます。学習の記録は残り、カードに戻すと続きから再開します。」の後に 4-12 の処理を行い、ノードの表示（関係側）に切り替える |
| カードの削除 | 一番下に「このカードを削除」（7-4 と同じ確認。孤立ノードの文を添える。4-12）。削除後は元のフォルダの単語一覧へ戻る |

**ノード側**

| 要素 | 仕様 |
|---|---|

| # | 判断 | 理由 |
|---|---|---|
| 1 | ノードは `words` と別のテーブル `nodes` に置き、Word の型を変えない | `words` を読む既存の処理すべてから、ノードを確実に外すため。除外の漏れがテストに頼らずに防げる |
| 2 | 関係は `kind`・`from`・`to`・`directed`・`label` の 1 レコードで持つ | 階層の向きは from（上位）→ to（下位）で表せ、連結の 2 つの向きも directed と from・to で表せるため |
| 3 | 2 つの項目の間の関係は 1 つだけ（種類と向きを問わない） | 「すでに関係のあるカードは選べない」という決定を、データの規則にしたもの |
| 4 | ラベルは 20 文字まで、候補は新しい順に 8 件 | 一言の短いラベルを想定し、行の右端に収まる長さにした |
| 5 | ノードの名前は 1〜200 文字、重複してよい | カードの表と同じ上限。同名でも別の概念のことがあるため |
| 6 | 孤立ノードの確認は、関係の ⊖ は専用の確認、各種の削除は既存の確認文に添え、スワイプ削除はトーストに添える | 削除の操作ごとに確認を増やさず、決定（A案：確認してから消す）を満たすため |
| 7 | 「ノードに戻す」は関係が 1 つ以上あるときだけ | 関係のないノードは存在できない（戻した瞬間に孤立する）ため |
| 8 | カードをノードに戻すとき、画像は消さずに残す | 再びカードにしたときに元に戻せるようにするため |
| 9 | ノードをカードにするときのフォルダの初期値は、saved のフォルダ → 関係一覧で最初のカードのフォルダ → 並び順で最初のフォルダ | 「関係のあるカードのフォルダを初期値にする」という決定に、戻したカードの場合を加えたもの |
| 10 | 関係一覧の並びは、上位・下位は名前の文字順、連結は記号ごとにまとめて文字順 | 一覧を開くたびに同じ順で出すため |
| 11 | 別フォルダのカードにはフォルダ名を添え、同じフォルダのカードには添えない | フォルダをまたいでいることを示しつつ、情報を増やしすぎないため |
| 12 | グラフの左は方向なしと「←」、右は「→」。各方向 3 件まで | 検討中の図の配置に合わせた。390px 幅に収まる数 |
| 13 | グラフの「戻る」は画面を離れる（中心の移動は履歴に積まない） | 戻るを何度も押さないと詳細画面に帰れない状態を避けるため |
| 14 | アウトラインは経路 10 本、各段 20 件まで。下位は 1 段目だけ開く | 大きな階層でも表示を軽く保つため |
| 15 | 追加シートの検索は最大 50 件、表（名前）の文字順 | ホームの検索（100 件）より狭い場所に出すため |
| 16 | 「ノードとして作成」は、名前が完全に一致する項目がないときだけ出す | 同じものを誤ってノードとして作るのを防ぎつつ、「該当がなければ出す」という決定を満たすため |
| 17 | ルートは `#/words/:wordId`（カード詳細、旧・単語フォームの編集）、`#/nodes/:nodeId`、`#/graph/:itemId?mode=` | 既存の URL を詳細画面に引き継ぎ、ノードを区別するため |
| 18 | 結果画面のポップアップの「カード」側には、学習の状態を出さない | 行にすでに評価と次の復習が出ているため |
| 19 | 兄弟の並べ替えは、直前のカードの兄弟でない最初のカードを選ぶ貪欲法 | 元の順序をできるだけ保ち、計算が単純なため |
| 20 | バックアップでは、端の欠けた関係と、関係のなくなったノードを捨てる | 孤立ノードを残さない規則（4-11）を、読み込みでも保つため |
| 21 | 関係の ⊖ の「元に戻す」は 5 秒、フォルダを変えたときのトーストは 4 秒 | 単語一覧のスワイプ削除（5 秒）と移動のトースト（4 秒）に合わせた |
| 22 | カード詳細画面で、メモが空なら見出しごと出さない | 関係のないカードでも画面を簡潔に保つため |
| 23 | グラフの「＋」は、上位・下位の並びの右端と、連結の並び（右側）の下に置く | 「区分ごとの＋」という決定を、図の配置の中で区分と対応がつく位置に置いたもの |
| 24 | ノードに戻したカードの ReviewLog は、学習カレンダー（7-11）とストリーク（6-7）でも数え続ける | 実際に学習した記録であり、カレンダーとストリークは ReviewLog だけを見る既存の仕様のままでよいため |
